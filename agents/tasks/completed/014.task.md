### 0.1 Clarification of an existing UI element (document it in the UI)
The **"Video cycle"** panel shows `master_cycle_*.mp4`: a **silent, seamless 45-minute loop** of the graded stock footage. It is the *building block*: the final video is this file looped (`-stream_loop -1 -c:v copy`) to the narration length. It is technically a "video without audio", but it is **not** the full-length video track. Feature A adds the full-length video-only export. Rename the panel to **"Video loop (building block, no audio)"** and add a one-line help text explaining the above.

### 0.2 Global rules (unchanged from Iteration 1)
- Never encode hours of unique video; re-encode only short heads/segments, loop everything else with stream copy.
- All intermediates share identical encoder settings (codec/profile/pix_fmt/GOP/timescale) so `-c copy` concatenation stays valid.
- Frame-quantize all durations used in offset math.
- No user-provided strings reach ffmpeg as raw filter text; validate and clamp numeric parameters server-side; pass argv arrays, never shell strings.
- Every stage is idempotent and cache-keyed by a content/params hash; write to `*.tmp`, atomically rename.

## 1. Feature A — Separate exports

### 1.1 Artifact registry
Introduce a single abstraction so UI and API do not need per-file special cases.

```ts
export type ExportKind =
  | 'narration'          // TTS voice only, no music, full length
  | 'background_music'   // music bed only, full length, project order/crossfades applied
  | 'mixed_audio'        // existing master_final.* (narration + music)
  | 'video_loop'         // existing silent master cycle
  | 'video_full'         // silent video, looped to target duration
  | 'final_mp4'          // video_full + mixed_audio muxed
  | 'greeting_clip';     // composed mascot greeting (if feature B enabled)

export interface ExportArtifact {
  kind: ExportKind;
  available: boolean;
  stale: boolean;            // inputs changed since it was built
  buildable: boolean;        // can be (re)built on demand without re-running upstream pipelines
  path?: string;
  sizeBytes?: number;
  durationSec?: number;
  container?: string;        // 'wav' | 'flac' | 'mp3' | 'm4a' | 'mp4'
  updatedAt?: string;
  formats: string[];         // available download formats (see 1.3)
}
```

`ExportService` resolves each kind to a file via existing services (do not duplicate path logic): audio pipeline for `narration`/`background_music`/`mixed_audio`, video module for the rest. `stale` = hash of inputs (script/voice settings/soundtrack revision/style/clip set/greeting config) differs from the hash stored with the artifact.

### 1.2 Producing the missing artifacts
1. **`narration`**: locate how narration is stored today (per-segment files or one file). If only segments exist, concatenate them losslessly (PCM/FLAC, same sample rate) with the same inter-segment gaps used in the mix, **no music, no ducking, no loudness change vs. the mix's narration stem** ("The narration is unchanged" per the soundtrack panel). If the mixing step already produces a narration stem, expose it instead of rebuilding.
2. **`background_music`**: render the bed to the same total duration as the mix, using the project's saved soundtrack revision (track order, crossfades, loop logic from `buildAmbientBed`). Query param `applyMixGain=true|false` (default `false` = unity gain, i.e. clean music for reuse; `true` = at the project's configured relative volume, e.g. −28 dB).
3. **`video_full`**: new job `POST /projects/:id/video/exports/video-full` with body `{ durationSec?: number; includeGreeting?: boolean }`.
   - `durationSec` defaults to the mixed audio duration; if audio does not exist yet, the UI must provide it (hh:mm:ss input).
   - Implementation: stream copy only, no re-encode when greeting is off:
     `ffmpeg -stream_loop -1 -i master_cycle.mp4 -t <dur> -an -c:v copy -movflags +faststart video_full.mp4`
   - When the greeting is on, use the head/body concat described in §2.7 so the result includes the greeting overlay.
   - Takes seconds, not hours. Report it as a job with progress anyway.
4. **`final_mp4`**: existing mux; just register it.

### 1.3 Formats
Audio artifacts: default `flac` for narration/music (lossless, ~half the size of WAV), plus `wav`, `mp3` (320k), `m4a` (AAC 256k). Transcode lazily on first request, cache under `exports/<kind>/<hash>.<ext>`. Note size estimates in the UI (4.5 h stereo 48 kHz WAV ≈ 3 GB). Video artifacts: `mp4` only.

## 2. Feature B — Mascot greeting with mouth animation

### 2.1 Product description
The channel mascot (an old bearded wizard on a glowing cloud, stylized 2D illustration, circular badge look) says a short greeting at the start of each video. The user generates character clips in **Veo 3** on their own account, uploads them to the app, and the app makes the mouth animation line up with the greeting voice-over generated by the existing TTS service.

Veo-generated clips are short (typically ≤ ~8 s) and Veo can generate its own audio; **the app must strip Veo's audio by default (`-an`)** because the voice must be the project's narrator voice.

### 2.2 Data model

```ts
export type CharacterClipRole = 'idle' | 'talk' | 'greeting_source';

export interface CharacterClip {
  id: string; role: CharacterClipRole; path: string; thumbPath: string;
  durationSec: number; fps: number; width: number; height: number;
  hasAudio: boolean;           // informational; audio is ignored unless lipSyncMode === 'native_veo_audio'
}

export type LipSyncMode = 'vad_switch' | 'external_lipsync' | 'native_veo_audio';
export type GreetingPlacement = 'pip_circle' | 'intro_fullscreen';

export interface GreetingConfig {
  enabled: boolean;
  text: string;                    // greeting text; default = first sentence(s) of the script
  leadInSec: number;               // silence before voice starts (default 0.6)
  tailSec: number;                 // character stays after voice ends (default 1.5)
  lipSyncMode: LipSyncMode;
  vad: { thresholdDb: number; minSpeechMs: number; minSilenceMs: number; hysteresisDb: number; windowMs: number };
  transitionMs: number;            // idle<->talk crossfade (default 200)
  placement: GreetingPlacement;
  pip: { position: 'bottom-right'|'bottom-left'|'top-right'|'top-left'|'center'; sizePctOfHeight: number; marginPct: number; feather: number; fadeInSec: number; fadeOutSec: number };
  externalProvider?: { id: string; options?: Record<string, unknown> };
}
```

Persist via `StateManagerService`. Store character clips under `<projectDir>/video/character/`. Treat character clips like stock clips for upload/ffprobe/thumbnail purposes (reuse the library services with a `scope` parameter instead of duplicating).

### 2.3 Greeting audio and timeline (integration with existing audio pipeline)
1. The greeting must be a **separate TTS segment** at the very start of the narration so its exact `[startSec, endSec]` in the master timeline is known. Inspect how the audio pipeline segments/concatenates narration; add a `greeting` flag/segment type if needed, with minimal change to the existing pipeline.
2. Expose from the audio layer: `getGreetingSegment(projectId): { audioPath, startSec, endSec } | null`.
3. If the pipeline cannot expose segment timings (single narration file), fall back to `ffmpeg silencedetect` on the narration head to find the end of the first sentence, and let the user adjust the marker on a waveform (UI §2.9).
4. Changing the greeting text invalidates the TTS segment and the mix. Show an explicit warning and a "Regenerate greeting audio & rebuild mix" action; never silently rebuild.
5. The video timeline equals the audio timeline: the greeting overlay is placed at `[startSec − leadInSec, endSec + tailSec]`.

### 2.4 Lip-sync strategies (`GreetingLipSyncStrategy` interface)

```ts
interface GreetingLipSyncStrategy {
  readonly mode: LipSyncMode;
  // Produces a character video whose duration == greeting window, ready for compositing.
  render(input: {
    greetingAudioPath: string; windowSec: number; clips: CharacterClip[]; config: GreetingConfig; outPath: string;
    onProgress: (p: number) => void; signal: AbortSignal;
  }): Promise<{ videoPath: string; durationSec: number }>;
}
```

#### 2.4.1 `vad_switch` — default, fully local, deterministic (P0)
Not phoneme-accurate: the mouth animates **while the voice is active** and rests during pauses. For a stylized 2D mascot this is the right cost/benefit trade-off and has no external dependency.
1. Decode greeting audio to mono PCM (e.g. 16 kHz) via ffmpeg; compute RMS in dBFS per `windowMs` (default 30 ms).
2. Smooth with hysteresis (enter speech above `thresholdDb`, leave below `thresholdDb − hysteresisDb`), enforce `minSpeechMs` (default 120) and `minSilenceMs` (default 180) to avoid flicker; merge short gaps.
3. Result: list of `{ start, end, speaking }` segments (frame-quantized).
4. Compose the character video from the `talk` and `idle` clips:
   - During `speaking` segments play the `talk` clip, looped seamlessly (self-crossfade loop as in Stage 1 extension, or continue from the last phase so mouth cycles don't restart each time).
   - During pauses play the `idle` clip (looped the same way).
   - Switch with a short crossfade (`transitionMs`, default 200 ms). Recommend generating both clips from **the same reference image with the same neutral start/end pose** so cuts are invisible.
   - If only one clip is provided (`greeting_source`), use it as both layers and apply a gentle effect during pauses (freeze on last neutral frame is NOT acceptable; instead loop the clip's first second). The UI must warn that quality is lower with a single clip.
5. Build with the **chunked approach** (segments → small clips → concat) to avoid giant filter graphs; the greeting is short (≈ 5–30 s) so a single filter_complex with trim/concat per segment is acceptable if the segment count is < ~60, otherwise chunk.
6. Output: silent MP4 at project resolution/fps with the same encoder flags.

#### 2.4.2 `external_lipsync` — pluggable provider adapters (P1)
Dedicated video-to-video / image-to-video lip-sync services exist that accept a source video (or image) plus a speech audio file (TTS is fine) and return a re-synced video; examples at the time of writing: Sync Lipsync v2, VEED Lipsync v2, VEED Fabric, OmniHuman. They generally need a clear, front-facing face and clean speech, and the output follows the audio duration. Capabilities and pricing change quickly: **the agent must verify the provider's current API docs before implementing an adapter and must not hard-code assumptions.**
- Define `LipSyncProvider` adapter: `submit(videoPath|imagePath, audioPath, options) → remoteJobId`, `poll(remoteJobId) → status/progress/resultUrl`, `download(resultUrl)`.
- Source video: build by looping the `talk` (or `idle`) clip to at least the greeting window length (reuse §2.4.1 loop logic), 1080p or lower per provider limits.
- Needs file upload/hosting for provider inputs (signed URLs or provider upload endpoint). Never expose project files publicly; use short-lived signed URLs or the provider's upload API.
- **Cost safety:** never call a paid provider automatically. Show estimated duration/cost (if the provider exposes it) and require an explicit confirmation click. API keys are server-side config only (`ConfigService`), never sent to the browser.
- Cache by `hash(audio, sourceVideo, provider, options)`; allow re-use without paying again.
- **Automatic fallback:** if the provider fails (e.g. no face detected on a cartoon character), return a clear error, keep the job recoverable, and offer a one-click switch to `vad_switch`.
- Ship with one reference adapter plus a `MockProvider` for tests; leave others as documented extension points.

#### 2.4.3 `native_veo_audio` (P2)
The user generates the greeting in Veo with its own speech. The app keeps Veo's audio for the greeting window and mixes it into the master timeline at `startSec`; the TTS greeting segment is skipped. Document clearly in the UI: **the voice will differ from the narrator**. Requires the audio layer to accept an external greeting audio file (loudness-normalize to the narration level with `loudnorm` two-pass or the existing normalization step).

### 2.5 Veo prompt helper (UI convenience)
Add "Copy prompt" buttons in the Character panel with editable templates. Defaults (English):
- **idle**: `Static locked camera. 2D storybook illustration style. An elderly wizard with wild gray hair, round glasses and a long white beard sits on a glowing cyan cloud under a starry night sky, reading a glowing book, eyes gently closed, slow breathing, beard and hair swaying very slightly, stars twinkling softly. No speech, no camera movement, no text. The last frame matches the first frame so the clip loops.`
- **talk**: `Static locked camera. Same character, same scene and framing as the reference image. Recommend using the character image as reference/first frame and keeping the same seed/style across clips. These are suggestions only; the app never calls Veo itself in this iteration.

### 2.6 Compositing (`GreetingCompositor`)
Inputs: character video (from §2.4), placement config, base `master_cycle` (silent).

**`pip_circle`** (default): circular badge over the underwater footage.
- Scale character video to `sizePctOfHeight` of frame height (default 28 %), crop to a square from the centre, apply a **circular alpha mask** with soft edge (`feather`, default ~2 % of diameter) — generate the mask once as PNG (or `geq` alpha expression) and apply with `alphamerge`; add an optional subtle outer glow.
- `overlay` at the configured corner with margin; `fade=t=in/out:alpha=1` using `fadeInSec`/`fadeOutSec`; enable the overlay only in `[start, end]` via `enable='between(t,s,e)'` or by timestamp-shifting the character stream with `setpts=PTS+<start>/TB`.
- Underwater video continues beneath; no change to the base timeline.

**`intro_fullscreen`**: character video covers the full frame (scale/pad onto a dark navy background matching the artwork) for the greeting window, then **cross-dissolves into the cycle** over `crossfadeSec`. The cycle keeps its own phase (it starts playing under the dissolve).

Both placements apply the same dark-sleep grade so the character does not glare against the dim footage (default: slight brightness reduction on the character, `eq=brightness=-0.08:saturation=0.9`), configurable.

### 2.7 Efficient assembly — re-encode only the head
The cycle is looped with stream copy, so only the beginning is re-encoded:
1. `N = ceil((greetingEnd + tailSec + fadeOutSec + (placement==='intro_fullscreen' ? crossfadeSec : 0)) / gopSec) * gopSec` where `gopSec` is the cycle's keyframe interval (2 s with Iteration-1 encoder flags). Cycle keyframes are at every `gopSec`, so `N` is a valid cut point.
2. Render `head.mp4` = composited video for `[0, N]` using the cycle's first `N` seconds as the base; encode with the **identical encoder settings** and `-force_key_frames` at `0` and `N` (and every `gopSec`).
3. Body = cycle from `inpoint N` through its end, then the cycle repeated as needed.
4. Concat demuxer list (`-c copy`):
   ```
   file 'head.mp4'
   file 'master_cycle.mp4'
   inpoint <N>
   file 'master_cycle.mp4'          # repeated M times, M = ceil((T - N) / cycleLen)
   ...
   ```
   then `-t <T>` to trim to the target duration. The visual is continuous at `N` because head ends on the same cycle frame at which the body resumes.
5. The same assembly feeds `video_full` (with `includeGreeting`) and `final_mp4`. Cache head by `hash(cycle, greetingConfig, characterVideo, N)`; changing only the audio length must not re-render the head.
6. Validate after assembly: ffprobe duration within one frame of target, no DTS warnings; extract frames around `N` into a debug folder when `VIDEO_DEBUG=1`.

## 3. Feature C — Particle / light overlay effects

### 3.1 Concept
Some stock clips get a particle/light layer on top (marine snow, bubbles, light shafts, dust motes, sparkles) which makes mixed footage feel cohesive and adds depth. Implement it as **per-clip effect layers baked into Stage 1 normalization** so they dissolve together with the clip during xfade, the master cycle stays one seamless artifact, and no whole-video re-encode is needed. (A global post-cycle overlay is intentionally out of scope: it would force re-encoding the entire timeline.)

### 3.2 Effect sources
1. **User overlay library (P0):** upload overlay videos (typical stock "particles on black background", also alpha-capable formats: WebM VP9 with alpha, MOV ProRes 4444/PNG-codec, or image sequences zipped). Normalize each overlay once to project resolution/fps (loopable, keep alpha where present), store under `<projectDir>/video/effects/<effectId>/`.
2. **Built-in procedural presets (P1):** generate loopable overlay clips locally on first use and cache them. Required presets: `marine_snow`, `bubbles_rising`, `light_rays`, `dust_motes`, `plankton_sparkle`. Approach hints (prototype, then **visually verify** each; the exact graph may need tuning):
   - Static random dot field rendered once (`geq`/noise → threshold → `gblur`), animated with the `scroll` filter (seamless wraparound; choose loop length as an integer multiple of the wrap period). Combine 2–3 layers with different speeds/scales for parallax using `blend=all_mode=screen`.
   - Light rays: soft diagonal gradient beams (blurred), slow sway via `rotate`/`scroll`, low opacity.
   - If ffmpeg-only generation proves awkward, use a small Node (`sharp`/`canvas`) or Python generator script behind the same `EffectGenerator` interface.
   - Presets must be deterministic by `seed` and loop seamlessly (first frame == frame after the last).

### 3.3 Data model

```ts
export type EffectBlend = 'screen' | 'add' | 'overlay_alpha';

export interface EffectDef {
  id: string; name: string;
  source: 'uploaded' | 'preset';
  presetKind?: 'marine_snow'|'bubbles_rising'|'light_rays'|'dust_motes'|'plankton_sparkle';
  path?: string; durationSec: number; hasAlpha: boolean; thumbPath: string;
  blend: EffectBlend;     // default 'screen' for black-background overlays, 'overlay_alpha' if hasAlpha
  opacity: number;        // 0..1, default 0.5 (grade is dark; keep subtle)
  speed: number;          // 0.25..2, default 1 (overlay playback rate)
  scale: number;          // 0.5..2, default 1
  maxBrightness: number;  // 0..1 cap so particles do not glare in dark footage (default 0.8)
  seed?: number;
}

// Added to StockClipMeta / per-clip settings:
interface ClipEffectAssignment { clipId: string; effectIds: string[] /* ordered, max 2 */ }

interface EffectRules {
  defaultEffectId?: string;
  applyToPercent?: number;      // 0..100, seeded random selection among enabled clips
  seed?: number;
}
```

Per-clip explicit assignments override rules. Effective effects for a clip are part of its Stage 1 cache key: `styleHash = hash(styleConfig, sorted effect ids + their params)`.

### 3.4 Stage 1 integration
Extend the normalization filtergraph (order matters):
```
[0:v] scale,crop,setsar=1, [hflip is NOT baked], setpts=<slow>*PTS, fps,
      eq(grade) [, self-loop extension via split+xfade if needed]   -> [base]
[1:v] (overlay input, -stream_loop -1) scale=W:H, fps, setpts=PTS/<speed>, format=<gbrp|yuva420p>, lut(maxBrightness) -> [fx]
[base][fx] blend=all_mode=screen:all_opacity=<opacity>:shortest=1    # or overlay for alpha sources
  -> vignette -> format=yuv420p -> [outv]
```
Rules:
- Apply the overlay **after** grading and after any self-loop extension (otherwise the internal crossfade would double the particles), but **before** the vignette (so edges still darken).
- Use `-stream_loop -1` on the overlay input and bound output with `-t <finalDuration>`.
- For multiple effects, chain blends in order (max 2 per clip).
- Pick a random overlay start offset per clip (seeded) so identical overlays on different clips are not in the same phase.
- Keep preview parity: the frame-preview endpoint must render the same overlay chain for the sample timestamp.

## 4. Feature D — Polish and checks from the screenshots

1. **Video loop player geometry:** the player in the "Video cycle" panel appears letterboxed/cropped (wide player area, content not filling it). Set `aspect-ratio: 16/9; width: 100%; object-fit: contain`. Additionally verify with `ffprobe` and an extracted frame that the file is genuinely 1920×1080 and **not** carrying black bars or an unexpected crop from the `scale/crop` step; fix the filter chain if bars are baked into the video.
2. **Banding in dark gradients:** visible vertical banding on the left of the sample frame (typical for heavy darkening + vignette in 8-bit, then worsened by YouTube re-encoding). Add a deband/dither step at the end of the Stage 1 chain (`gradfun=strength=<~1.0>:radius=16` and/or very light temporal noise `noise=alls=2:allf=t`), and for dark content use x264 `aq-mode=3` and a slightly lower CRF (≈ 18–19) for Stage 1 outputs. ## 6. Acceptance criteria
- Narration, background music, mixed audio, video loop, full-length silent video and final MP4 can each be downloaded individually; ZIP of any subset streams without memory growth; Range requests work.
- `video_full` for a 4.5 h target finishes in seconds to a couple of minutes (stream copy), duration within one frame of the request.
- Narration export contains no music; music export contains no narration; both match the mix's total duration.
- Particle effects can be assigned per clip, in bulk, and by percentage rule; effects dissolve together with their clip at crossfades; the master cycle remains seamless (loop seam test still passes); cache invalidation only touches affected clips.
- Greeting: with `vad_switch`, mouth animation visibly follows speech/pause segments of the greeting audio without flicker; the greeting overlay appears/disappears smoothly; the seam at `N` between head and body is invisible; no A/V drift over 4.5 h; changing only audio length does not re-render the head.
- External providers are never called without explicit confirmation; failures fall back gracefully.
- No secrets are sent to the browser; all numeric parameters are validated and clamped.
