# Frontend Plan: Ambient Library and Stem Downloads

## Goal

Give users a browser interface to manage the ambient music library and make the generated voice, music, and mixed deliverables individually downloadable. Music remains optional: projects without active ambient tracks still complete and expose their voice-only output.

## Current frontend behavior

- `DownloadsPanel` offers mixed WAV/FLAC links, timestamps, markers, and chapter WAV files.
- The typed `MediaArtifact` union and project output state represent only `wav`, `flac`, `timestamps`, and `markers`.
- The create-project form is profile-driven, but there is no ambient-library page or upload/list/order/enable/delete UI.
- Media download URLs are generated by the existing `apiClient.media` wrapper and should continue to use normal browser downloads.

## Planned experience

### Ambient music library

Add a dedicated navigation destination/view (for example `Music library`) that works independently of a selected project. It should:

- List managed tracks in the exact playlist order the backend will use, showing display name, enabled/disabled state, and any useful audio metadata returned by the API.
- Upload WAV files with clear file type/size requirements, progress/pending feedback, duplicate/error feedback, and success confirmation.
- Enable/disable tracks without deleting them; disabled tracks are excluded from future mixes.
- Reorder active tracks and persist the order through the API. Use accessible buttons/controls and announce changes; drag-and-drop may be supplementary, not the only mechanism.
- Delete a track with a confirmation step and update/refetch the React Query cache.
- Explain that this is a shared library and its enabled, ordered playlist is used for new mastering jobs. Removing or reordering library assets must not silently alter already-rendered project files.

Use the existing React, TanStack Query, Axios client, UI primitives, and toast/error patterns. Add typed API methods and query/mutation hooks for the ambient routes. Do not add a new client library without need.

### Production downloads

Extend frontend types and `DownloadsPanel` for:

- Voice-only WAV and FLAC stems.
- Music-only WAV and FLAC stems when a project was mixed with ambient music.
- Existing full mixed master WAV and FLAC.
- Existing timestamps, markers, and per-chapter files.

Use artifact availability in `state.outputFiles` to gate each link. Label the full mix clearly; do not alias the voice-only output to the mixed-master link. Explain why music/mix links may be absent (no enabled music tracks were available at mastering). Keep all audio downloads on the existing streaming URL mechanism.

## Frontend implementation sequence

1. Extend `MediaArtifact`, `ProjectState.outputFiles` typing, and API response types for voice/music stems and ambient library records.
2. Add typed ambient API methods and TanStack Query hooks for listing, uploading, updating enabled state/order, and deletion; invalidate the library query after mutations.
3. Add an accessible ambient-library view and navigation entry, including empty/loading/error states, upload validation/progress, ordered list, enable toggles, reorder controls, and confirmed deletion.
4. Update `DownloadsPanel` with distinct voice-only, music-only, and mixed WAV/FLAC downloads, availability guards, and clear explanatory copy.
5. Add UI/API-hook tests using existing test conventions; ensure current downloads and project workflows remain intact.
6. Run frontend tests, lint (if feasible), and production TypeScript/Vite build.

## Acceptance criteria

- A user can see the ambient playlist, upload a WAV, enable/disable it, reorder it, and delete it from the browser.
- The interface communicates the global/shared nature and actual processing order of the playlist.
- On a project with music, users see separate voice, music, and mixed downloads in WAV and FLAC where advertised by state.
- On a project without music, voice-only downloads and metadata remain available; music/mix links are absent or clearly unavailable.
- Existing timestamps, marker, chapter, and mixed-master download behavior remains correct.
- Loading, empty, failed, uploading, and mutation-pending states are usable and accessible.
