# Task 002: Zod Schemas (`schemas/`), TypeScript Types (`types/`), and `StateManagerService`

## Objective
Establish strict data validation and typing using dedicated `schemas/` (`*.schema.ts`) and `types/` (`*.type.ts`) directories, and implement an atomic, fault-tolerant `StateManagerService` for disk persistence.

## Implementation Details
1. Create `/backend/src/schemas/` where every file uses the `.schema.ts` suffix:
   - `profile.schema.ts`: Validates generation configuration (`architectModel`, `writerModel`, `architectReasoningEffort`: `'none' | 'low' | 'medium' | 'high'`, `writerReasoningEffort`: `'none' | 'low' | 'medium' | 'high'`, `temperature`, `architectSystemPrompt`, `writerSystemPrompt`, `ttsVoice`, `ttsSpeed`, `maxChunkChars`, and `masteringConfig`).
   - `outline.schema.ts`: Validates LLM outline output (`topic`, `totalChapters`, `chapters` array with `chapterNumber`, `title`, `keyScientificFacts: string[]`, `sensoryThemes: string[]`, `targetWordCount`).
   - `state.schema.ts`: Validates `state.json` (`projectId`, `topic`, `createdAt`, `updatedAt`, `status`: `'IDLE' | 'GENERATING_OUTLINE' | 'GENERATING_SCRIPTS' | 'SYNTHESIZING_AUDIO' | 'MASTERING' | 'COMPLETED' | 'FAILED'`, `error?: string`, `profile`, `outlineCompleted: boolean`, `chapters` record containing chapter script status, TTS status, `durationMs`, and `chunks` array with `id`, `index`, `text`, `pauseAfterMs`, `status`, `filePath`, `durationMs`, plus `outputFiles` paths).
2. Create `/backend/src/types/` where every file uses the `.type.ts` suffix:
   - `profile.type.ts`, `outline.type.ts`, `state.type.ts` exporting static types via `z.infer<typeof ...>`.
   - `llm.type.ts` and `tts.type.ts` defining service contract interfaces (`ILlmService`, `ITtsAdapter`).
3. Implement `StateManagerService` in `/backend/src/modules/state/`:
   - `initProject(topic, profile)`: Generates a URL-safe project slug (`001-topic-slug`), creates `/projects/<projectId>/` with subdirectories `chapters/`, `chunks/`, `chunks/silence/`, and `output/`, and writes the initial `state.json`.
   - Atomic write mechanism: Always write to `state.json.tmp` and use `fs.promises.rename` to overwrite `state.json` to prevent file corruption during crashes or concurrent UI polling.
   - Idempotency helpers: `getPendingChapters(projectId)`, `getPendingChunks(projectId, chapterNumber)`, `markChunkCompleted(projectId, chapterNumber, chunkId, durationMs)`, `markChapterAudioCompleted(projectId, chapterNumber, durationMs)`. Each helper must check both the status in `state.json` AND verify `fs.existsSync(filePath)` on disk.

## Verification Criteria
- All Zod schemas reside strictly in `src/schemas/*.schema.ts` and all types in `src/types/*.type.ts`.
- Unit test `state-manager.spec.ts` creates a temporary project, validates `state.json` against `stateSchema`, marks 2 of 4 chunks as completed (creating dummy `.wav` files), deletes 1 `.wav` file on disk to simulate corruption, and verifies that `getPendingChunks()` accurately returns the missing disk file chunk alongside the remaining uncompleted chunks.
