# Task 005: Kokoro-FastAPI TTS Adapter & Sequential BullMQ Worker

## Objective
Synthesize audio chunks sequentially (`concurrency: 1`) using the Dockerized Kokoro-82M GPU container with voice blending, validating each output `.wav` via `ffprobe`.

## Implementation Details
1. Implement `KokoroTtsAdapter` (implementing `ITtsAdapter` from `src/types/tts.type.ts`) in `/backend/src/modules/tts/`:
   - Send HTTP `POST` requests to `${KOKORO_API_URL}/v1/audio/speech`:
     ```json
     {
       "model": "kokoro",
       "input": "<chunk.text>",
       "voice": "bm_george*0.65+bm_lewis*0.35",
       "speed": 0.85,
       "response_format": "wav"
     }
     ```
   - Stream the binary response directly to `/projects/<projectId>/chunks/ch_XX_chunk_YYY.wav`.
2. Implement `TtsProcessor` BullMQ worker in `/backend/src/modules/tts/`:
   - Set `@Processor('tts-queue', { concurrency: 1 })` to strictly serialize GPU inference.
   - Before synthesizing, check `StateManagerService` to skip if the chunk is already `'COMPLETED'` and valid on disk.
   - After writing the `.wav` file, run `ffprobe` to verify the file is a valid audio stream with duration `> 150ms` and read its exact `durationMs`.
   - Update `state.json` via `StateManagerService.markChunkCompleted()`.
   - **State Transition Trigger:** Check if all chunks across all chapters in `state.json` have reached `'COMPLETED'`. When the final chunk of a chapter finishes, enqueue `assemble-chapter` for that chapter in the `audio-mastering` queue.

## Verification Criteria
- Integration test (or mock TTS server test) processes 5 chunks strictly sequentially (`concurrency: 1`), writes `.wav` files, measures duration via `ffprobe`, updates `state.json`, and triggers `assemble-chapter` only when the 5th chunk completes.
