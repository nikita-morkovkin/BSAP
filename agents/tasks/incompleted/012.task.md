# Task 012: Separate Voiceover and Background Music Downloads with Bulk Export

## Objective

Allow users to download the full voiceover and each background music file separately, or download all project audio sources together in one archive without combining them into a single audio file.

## Dependencies and Current Implementation

- Implement Task 011 first: this plan uses its ordered project selection, immutable music snapshots, and revision-safe mastering contract.
- `n:\Projects\BSAP\backend\src\modules\audio\ffmpeg.service.ts` already creates `output/voice_raw_full.wav` by concatenating assembled chapters, but does not register it in `state.outputFiles`.
- `n:\Projects\BSAP\backend\src\modules\projects\media.controller.ts` and `media.service.ts` expose streamed downloads for mixed WAV/FLAC masters, timestamps, markers, and individual chapters. Their realpath containment checks must be retained for new routes.
- `n:\Projects\BSAP\frontend\src\views\downloads\DownloadsPanel.tsx` uses native download links and artifact availability, avoiding browser-memory buffering of long audio.
- Neither package manifest currently declares a ZIP library. Archive tooling selection is an explicit prerequisite, not an assumed installed dependency.

## Scope and Export Semantics

- Voiceover means the complete narration-only WAV, assembled from chapters with the existing chapter/chunk pauses and no music. Expose the existing raw concatenation; label it clearly as unmastered narration, not the mixed final master.
- Background music downloads are the original selected project source snapshots, one file per track, before speed/volume/crossfade processing. They are not the ambient cycle or a mixed music stem.
- The default project bulk export contains the voiceover, every included music source as a separate file, and a manifest. It excludes unchecked library tracks, mixed masters, chapter duplicates, and internal temporary files.
- Provide an additional Download all library music action in the Music Library so that users can also retrieve every library source regardless of project inclusion. Inclusion checkboxes control production, not whether a library file can be downloaded.
- An empty project selection yields a valid voiceover-only project archive. An empty library disables its bulk download with an explanation.
- A processed, duration-matched ambient stem or separately mastered voice stem is a future enhancement, not a substitute for the required source-file downloads. Use clear UI labels to avoid implying these are offered.

## Implementation Plan

### 1. Artifact State, Availability, and Recovery

- Extend Zod output schemas, inferred backend types, frontend types, and artifact validation to register `voiceover` after the full narration WAV is atomically written and probed successfully.
- Preserve valid voiceover availability if later music mixing fails. Do not clear it merely because the music selection changed. Invalidate it when chunk/chapter narration is regenerated.
- Track narration revision separately from music selection revision. Associate export metadata with the exact committed versions of narration and music snapshots, not just project status.
- Expose a project source-download manifest describing voiceover and selected sources, with IDs, safe download names, MIME types, sizes, durations, source versions, availability, and revision. Do not expose absolute paths.
- Handle legacy projects explicitly: safely register an existing verified `voice_raw_full.wav`; if absent, use the existing queue to concatenate completed chapters on an explicit rebuild/resume action without LLM/TTS work. Do not generate media as a side effect of GET requests.
- Preserve compatibility for existing `wav`, `flac`, `timestamps`, and `markers` downloads and resume checks.

### 2. Individual Download Endpoints

- Extend `GET /api/projects/:id/media/download/:artifact` to accept `voiceover` and return the full narration WAV through the existing streaming service.
- Add `GET /api/projects/:id/media/sources` for source availability and revision metadata.
- Add `GET /api/projects/:id/media/music/:trackId/download` to resolve a source exclusively from the committed project snapshot, never from the mutable global catalog.
- Add `GET /api/music/:trackId/download` for individual current-library sources. Keep library and project routes clearly distinct.
- Use safe attachment filenames and correct MIME type/length headers. Resolve all client IDs against validated metadata; reject traversal and escaped symlinks on Windows and Linux. Never accept arbitrary download paths.
- Return 404 for absent files, 409 for stale/inconsistent revisions or incomplete required exports, and actionable errors. Do not equate overall project completion with individual source availability.

### 3. Bulk Archive Infrastructure

- Use ZIP for ordinary desktop interoperability, including ZIP64 support for multi-hour files/archives above 4 GiB. Never buffer the full archive or its audio entries in memory and never launch multiple automatic browser downloads as the bulk solution.
- Before implementation, review and approve a maintained streaming ZIP implementation compatible with the installed Node/NestJS versions, then add the explicit dependency and lockfile changes. No such library is currently confirmed in this repository; do not import an assumed dependency or assume a system ZIP command exists. This is an implementation prerequisite requiring dependency approval if repository policy demands it.
- Add `GET /api/projects/:id/media/sources/download-all?revision=...` for the project ZIP and `GET /api/music/download-all?revision=...` for the library ZIP. Register the static library route ahead of parameterized track routes.
- Preflight the requested manifest/revision and every required file before sending archive headers. If any required source is missing, fail explicitly rather than silently returning an incomplete successful archive.
- Pin immutable source versions for the duration of each export. Coordinate project deletion, library deletion/replacement, and snapshot garbage collection with active exports; release file leases on success, abort, or error.
- Project archive layout: `voiceover/voiceover.wav`, `music/<stable-track-id>_<safe-name>.wav`, and `manifest.json`. Library archive layout: `music/<stable-track-id>_<safe-name>.wav` and `manifest.json`.
- Include scope, revisions, track order, source IDs/versions, original names, durations, sizes, and relevant mix settings in the manifest. State explicitly that music entries are original sources and voiceover is unmastered. Do not include credentials, prompts, or absolute paths.
- Stream archive entries with backpressure, bounded resources, ZIP64 support, and per-request cancellation. Enforce a bounded concurrent-export limit to protect local disk I/O.
- Propagate pre-header errors as structured HTTP failures; abort the connection and record an actionable error if a source read fails after streaming starts. Ensure aborted exports release streams and leases; no cache/temp-file leaks.
- Prefer on-demand archive streaming, with no persistent duplicate archive. If disk-backed staging becomes necessary, define revision-keyed reuse, bounded disk retention, restart cleanup, and project deletion integration before adding it.

### 4. Frontend Download Experience

- Extend `n:\Projects\BSAP\frontend\src\api\media.api.ts` and Task 011's music domain API with typed manifest calls and URL builders through the existing Axios instance/aggregator pattern.
- Add a separate Source audio section to `DownloadsPanel.tsx`: Download voiceover (.WAV), one download row per included music file, and Download voiceover + selected music (.ZIP).
- Display the selected source list and its count from the committed project manifest, not the current global catalog. Explain that excluded tracks are not in the project bundle and link to Music Library for all-library exports.
- Add individual source download links and Download all library music (.ZIP) to the Music Library view.
- Use native anchor downloads, consistent with existing `DownloadLink.tsx`. Do not fetch large audio or archives into Axios blobs or JavaScript buffers. Pass the displayed revision to bulk endpoints to prevent stale exports.
- Disable unavailable links and explain whether narration must be assembled, a source is missing, a mix needs rebuilding, or no library tracks exist. Individual sources may remain downloadable even when the mixed master failed.
- Invalidate/refetch availability after narration regeneration, music selection saves, remastering, and library mutations. Do not present stale sources as a newly completed mix.
- Provide a lightweight preflight action for useful UI feedback before starting a native bulk download. Do not claim browser download completion or byte-progress tracking from a native link; those remain browser-managed.
