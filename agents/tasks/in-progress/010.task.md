# Task 010: Ambient Music Library UI and Stem Downloads

## Objective

Add a frontend interface for managing the shared ambient WAV library and expose the new voice-only and music-only exports alongside the existing mixed master downloads.

## Related plan

- `/agents/tasks/FRONTEND_PLAN.md`

## Implementation details

### 1. API and type integration

1. Extend `/frontend/src/types/project.types.ts` with voice/music download artifact keys and output-file paths. Keep the existing `wav` and `flac` keys as the mixed master.
2. Add typed ambient record/request types (track ID, display name, enabled state, order) and API methods in the current `/frontend/src/api/` organization for list, multipart WAV upload, update enabled/display name, reorder, and delete.
3. Add React Query hooks/mutations for the ambient endpoints. Invalidate/refetch the ambient library after successful mutations; surface actionable errors through current app conventions.

### 2. Ambient library interface

1. Add a dedicated music-library view and navigation destination that can be used without opening a particular project.
2. Render tracks in backend playlist order and clearly show which are enabled and therefore used in future mixes.
3. Add WAV upload with accepted format/size guidance, pending/progress state, success feedback, and API error handling.
4. Add accessible enable/disable controls, reorder controls (keyboard/button operation must work without drag-and-drop), and confirmed delete actions.
5. Provide loading, empty, failed, and mutation states. Explain that the library is shared across new mastering jobs and that already-generated outputs are not retroactively changed by library edits.

### 3. Downloads interface

1. Update `/frontend/src/views/downloads/DownloadsPanel.tsx` to provide distinct voice-only WAV/FLAC downloads, music-only WAV/FLAC downloads, and the existing mixed-master WAV/FLAC downloads.
2. Gate each link using `state.outputFiles`; do not show an enabled link when that artifact is absent. Explain that no music/mix is available when no enabled ambient tracks were present at mastering.
3. Preserve timestamps, marker, and per-chapter downloads and use existing `apiClient.media.downloadMediaUrl()` streaming URLs.

### 4. Tests and verification

1. Add/update tests for ambient library API hooks/view behavior: initial list, empty state, upload success/failure, enable toggle, persisted order, deletion confirmation, and refetch after mutation.
2. Add/update downloads view tests for projects with all outputs and projects with voice-only outputs; verify absent links are not rendered or are explicitly disabled.
3. Confirm navigation works without a selected project and existing create/monitor/download flows remain functional.
4. Run frontend tests, lint where feasible, and `npm run build` from `/frontend`.

## Acceptance criteria

- Users can manage the shared ambient playlist from the frontend: upload, list, enable/disable, reorder, and delete WAV tracks.
- The UI accurately communicates that enabled tracks and their order drive future background mixes.
- Users can download voice-only stems independently from music-only stems and the full mixed master.
- Music and mixed download controls are only available when backend state says those outputs exist.
- Existing timestamps, markers, chapter downloads, and mixed master links continue to work.
- Frontend tests and production build pass.
